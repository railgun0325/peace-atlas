# 阅读条件候选历史：受控通过，真实结束引用仍失败

本记录对应标准 DSH 报告的引用条件修复候选。新源码已冻结，320 项相关回归及实际 SDK 的受控恢复闭环通过；后端、前端、桌面和打包器共 3,174 项整套回归通过。本次新包、正式 601 来源报告、Windows/Mac 原生分发与最终私有 Release 均须完成独立验收。此前质量版记录见[历史质量发布](RELEASE_QUALITY_20261011.md)，不替代本候选的结果。

## 实际故障与修复

真实 601 条来源任务完成逐条审阅后，DSH 的结束候选因摘录绑定失败而停止。来源审阅完成、逐字摘录检查成功、实际工具原文阅读和报告完成分别是不同条件，不能用某个中间进度表示最终报告已保存。

此前先补充 `quote_schema`、`citation_not_in_finding`、`citation_not_read` 固定分类和从 1 起始的 finding/quote 位置；最终失败诊断与最后发送的纠正反馈分别保存。相同输入恢复带入安全位置和固定指导，旧记录缺少位置时保持未知；诊断不保存任意引用 ID、摘录或被拒候选正文。

引用反馈候选的正式续跑保留全部 601 条阅读和 130 条工具记录，但单轮回复在 16,384 token 的预留下返回 `length`。对应源码与 3,134 项整体回归保留为[反馈候选清单](release-evidence/feedback-source-manifest-20261011.json)和[反馈候选测试](release-evidence/feedback-source-tests-20261011.json)。

后续容量候选取消 SDK 初始化 16K 和 host 转发 32K 的固定低上限。官方 DeepSeek Flash 最大输出为 393,216 token；思考与回答共享生成额度，完整输入和输出仍须装入上下文。工作台统计工具描述、历史思考、参数和结果，按完整 wire 的剩余上下文调整实际预留并复查。未知提供商和显式小容量配置继续按自身容量处理，超配置请求在 HTTP 前拒绝；截断不自动重试或采用不完整结果。[官方接口容量与结束原因](https://api-docs.deepseek.com/api/create-chat-completion/)

该容量候选通过 3,154 项整体回归、本机组装和实际包内 SDK、隔离 Windows 原生启动与备份、正式 23 张表无迁移升级；其正式续跑实际预留 393,216 token，完整回复进入最终校验，仍因缺少真实工具阅读而失败，没有保存新报告。该候选保留为[容量候选清单](release-evidence/output-source-manifest-20261011.json)和[容量候选测试](release-evidence/output-source-tests-20261011.json)。一次中间一致性读取检查失败也保留，后续稳定读取按同一守卫重新核对通过；不能描述为所有中间检查均成功。

脱敏结构核对显示：正式续跑新增十次调用都是成功 `check_citation`，其中一条没有同编号的成功 `read_evidence`，也没有覆盖摘录的既读窗口。这证明“匹配成功但未实际阅读”确实发生；被拒候选没有保存，不能将该条工具记录直接认定为最终 finding 16、quote 1。

本次在标准报告的模型工具反馈及恢复上下文中分别给出 `report_quote_ready` 和固定 `report_quote_gap`。当缺少阅读或阅读窗口没有覆盖摘录时，`next_read` 根据当前 gateway 重新核验的编号、Unicode 偏移和摘录长度提供合法补读参数。它帮助模型自行补读，未替模型执行读取，也未把文字匹配升级为事实核验。

原纯 gateway 结果仍按原样持久化，旧父任务和完整 trace 不重写。gateway、工具 schema、`SYSTEM`、研究指纹定义、严格最终 validator 及自动审核的自定义结束合同保持。模型不能靠该提示跳过逐字核对或实际阅读；同一恢复链累计最多两次纠正，换包或续跑不清零。

## 冻结源码与本轮测试

应用 freeze SHA256 为 `11bf136ce51673a63650a4c01250b46e899f1f82f8b40cfee7fa16e9cb9a056f`。固定 3,153 个应用文件：Windows 3,139、Mac 3,142；测试源文件 148。[源码清单](release-evidence/readiness-source-manifest-20261011.json)仅含相对仓库路径和摘要，不含本机路径、配置或研究材料。

后端 2,889、前端 198、桌面 62、打包器 25，共 **3,174 项通过，0 失败**；后端耗时 501.64 秒。各组在执行前后核对同一冻结的应用及测试字节，[公开整套测试记录](release-evidence/readiness-source-tests-20261011.json)绑定本轮清单。包内、原生和真实模型验证分别记录。

九组相关回归共 320 项通过、0 失败、54.80 秒，包含新增 20 个阅读条件行为用例，覆盖真实匹配与阅读的区别、旧参数异常、伪造偏移/hash、重复摘录的第二个有效阅读位置、Unicode/空白、恢复、传输、输出容量、取消和自定义审核。红例和独立子审发现的异常分支均先保留失败再修复。相关计数与整套回归重叠，不能相加。

源码 Python、真实 host 与实际 vendored SDK 的受控闭环使用三次 MockTransport HTTP、零真实模型、零外网：恢复 140 条工具记录时首次请求可见缺口，模型实际执行 read 141 和 check 142，第三次提交完整结束对象并由原严格 validator 接受。父状态与原 140 条 trace 前缀字节不变，新增持久结果仍是纯 gateway 结果；累计纠正保持 2，没有新增修正；完成 checkpoint 再恢复为零新 HTTP。它证明受控运行合同，不代表新包或真实 DeepSeek 必然成功。

新的正式续跑任务为 `b67c6e5e-1a29-41fd-b802-c4f5a5e141f2`，沿父任务 `a987e4aa-64f9-4f88-af96-382c969c146b` 的原输入创建。真实模型在一轮新请求后仍被严格结束校验以 `unchecked_quote` 拒绝，没有新增工具调用或保存正式报告。实际输出预留为 393,216 token，上下文没有迫使它降低；传输与输出截断不是本次错误。结束时逐项核对全部 601 条来源阅读与 140 条原工具前缀完全相同，父记录未改写，累计两次纠正也未重置。受控恢复成功并不代表真实模型的取证策略已完成验收，本轮核心仍待修复。
