# 桌面恢复闭环计划 · 2026-10-08

上一轮完成在线备份、实际下载和独立目录恢复验证，但用户恢复仍需退出后手工置换数据库。本轮把桌面恢复补成可操作流程，保留旧库和原始备份，并对失败与异常退出建立明确回退路径。

## 交付与验证要求

1. 设置页提供“恢复研究备份”，由桌面原生文件选择器选择文件。浏览器版保留手工说明。
2. 在停止当前后台之前，独立运行时只读检查原始备份，并产生已检查的独立候选库。验证文件、当前兼容结构、JSON 字段、完整性和外键，拒绝带未合并 WAL 的直接数据库副本。
3. 显示备份数量与恢复影响，由应用用户在原生窗口明确确认；取消或校验失败时当前工作台继续运行。
4. 后台确实退出后才更换数据库。自动保留完整旧库和必要 sidecar，不更改登录会话、AI 连接或原始备份。
5. 候选库中的排队与运行任务中断，保留记录并要求手动重试；恢复本身不触发采集、登录或 AI。
6. 文件操作或候选启动失败时回退旧库。持久记录恢复阶段；下次启动发现未完成恢复时先安全处理，不能把缺失的旧库当作正常首次运行而创建空库。
7. 通过实际设置页操作、私有 Python、后台重启与 SQLite 实物检查验证；记录恢复前后内容、旧库存档、源文件指纹及凭证文件未变。
8. 修改稳定后重新构建 `-recovery-candidate`，核对当前源码、清单和包内字节，保持 Windows x64 / Apple Silicon 交付范围及既有外部平台验收边界。
