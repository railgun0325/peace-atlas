# 报告质量修复与最终交付候选

日期：2026-10-11。产品版本 2.0.0，资产后缀 `foundation-quality-20261011`，计划私有标签 `v2.0.0-foundation-quality.20261011`。当前尚未发布；固定的旧 recovery 标签和已受测资产保留。

本批在 [报告续跑验收](RELEASE_RECOVERY_20261011.md) 的真实成功报告上发现内容质量问题后继续修复。两处同平台 X 用户名大小写差异被错误解释成账号对应关系未核验；另有竞争解释使用“更可能”但没有比较证据。运行成功、来源覆盖通过和模型接受，均不能替代独立内容复核。

## 实际修改

- 来源库存保留原样句柄、偏移、引用与目标绑定，复用现有 X 用户名规范化规则，为成稿和最终来源复核提供同一映射。规范化不授予组织运营身份、互认、隶属或迁移关系核验，不合并不同拼写和跨平台账号。
- 确定性检查只拦截保存简介和同平台已登记目标支持的明确同键用户名矛盾。原样写法差异、组织主体未核验、否定句和准确归因的来源引文保留。
- 成稿协议升为 5，受影响旧草稿指纹失效；父任务、旧报告与完整候选历史保留。比较性解释缺少依据时，成稿政策与来源复核要求修正，不以通用概率词正则代替语义核对。
- 证据笔记缓存只投影本轮新增的规范化提示字段，原文、真实绑定、偏移、范围、供应商及压缩提示仍严格匹配。更新报告政策不会使未变化的已审核笔记全部重做。
- 随包自动审核说明修正审核任务和普通任务取消、重试所需的 `review`／`run` 授权。主说明书同步更新原生导出步骤与结论边界。

## 已完成的定点验收

新增 38 项行为回归；统一执行的 328 项报告相关回归通过，0 失败，74.06 秒。真实报告的两个完整错误段落在离线探针中各触发一个窄范围阻断；正确的主体限定和否定措辞通过独立边界复验。新的来源复用合同保留已有正文、绑定与范围变化的失效行为。

使用真实 `fit_report_input` 和受控 HTTP 测得：旧协议首次运行需要 12 次压缩／笔记复核请求；新协议继续复用全部 6 个已审核笔记批，新增压缩请求为 0，只有成稿与最终来源复核各一次。临时 Store/API 两任务回归也复用既有阅读和 Harness 结果，父检查点未改变。这些是受控行为测量，不是实际账单、真实模型可靠性或实际耗时提升的证明。

旧正式报告原生另存为已通过，Markdown 852,380 字节且与保存全文哈希一致；临时文件曾是在等待系统保存确认，没有据此修改桌面下载逻辑。说明书离线 HTML 的 20 部分、26 参数表在桌面及手机宽度下通过浏览器检查，页面错误与横向溢出均为 0。
