# Workbench v2 implementation contract

Scope: a local-first, source-backed Japan peace research workbench. Preserve original runtime data and secrets. No fabricated demo data in the live application. Old collectors are reusable adapters, not proof of current platform availability.

## Module boundaries

- `app/workbench/store.py`: durable repository. SQLite by default (`WORKBENCH_DB_PATH`), optional PostgreSQL (`WORKBENCH_DATABASE_URL`). Separate `wb_*` tables. String UUID IDs, ISO UTC timestamps, JSON stored as text for portability.
- `app/workbench/pipeline.py`: pure enrichment, collector adapters, report generation. No persistence. Reuse tested cleaning, URL normalization, Japan topic/entity/geo rules.
- `app/workbench/jobs.py`: durable queue orchestration, recovery and cancellation, calls pipeline and repository.
- `app/workbench/social/`: bounded X / Instagram collection and session verification. No legacy database/scheduler/AI dependency; independent platform sessions under the active user data directory. The bundled Chromium runtime performs collection and verification, while the normal user sign-in flow opens the OS default browser.
- `app/workbench/social/auto_session.py`: authorized existing-session reuse. Verify the saved workbench session first; only a missing session or explicit login-required result allows fallback to the single available registered default Firefox profile. Challenge, rate limit, ambiguous identity or an unconfirmed verification result stops the check. Never launch a new sign-in or a visible browser here.
- `app/workbench/social/firefox_import.py`: narrow reuse of one registered Firefox profile's platform session. Profile listing reads only the profile index and file availability. Cookie reads occur during an authorized automatic reuse or explicit profile import; authenticated platform-home verification is required before backing up and atomically replacing workbench state. No passwords, other-site sessions, full-profile copying, profile modification or new sign-in.
- `app/workbench/social/external_browser.py`: fixed official platform URLs dispatched through the OS URL-opening mechanism. No user-supplied target URL, browser executable/profile selection, fallback automation browser or inferred login success.
- `app/workbench/social/browser_bridge.py` and `browser-extension/`: optional Chrome / Edge MV3 session transfer through the browser's authorized cookies API. One-use local pairing, platform-and-extension-bound token, exact session-field allowlist, live verification before saving. No password access or browser database decryption. Extension installation and real-browser acceptance are separate from source and offline-test completion.
- `app/workbench/relevance.py`: explainable Japan peace research gate, applied before discovery budgets; focused/broad are explicit user choices. No silent AI calls.
- `app/workbench/legacy_import.py`: explicit read-only legacy collector migration, unknown dates and candidate status retained.
- `app/workbench/server.py`: FastAPI application factory, validation and API routes. Default new entrypoint through `app.main:app`; original app preserved as legacy module.
- `app/static/workbench/`: modular browser frontend; no inline onclick, no external runtime CDN, responsive constructivist design.

## Repository interface

`Store(path=None, database_url=None)` initializes schema. All methods return JSON-compatible dicts.

- `import_items(items)` -> `{inserted, updated, duplicates, rejected, issues, ids}`; normalized entries contain title,url,content,source_name,type(news/social),published_at,topics(list[str]),entities(list[str]),locations(list[dict]),account_id(optional). Transactional dedupe. A proven social recapture may fill missing author/date/body while retaining its old capture in a revision; existing report snapshots remain immutable.
- `list_items(query='',type='',topic='',source='',start_date='',end_date='',page=1,page_size=25)` -> `{items,total,page,page_size}`. End date inclusive, unknown publication date explicitly flagged. `get_item(id)` -> item or None.
- `overview()` -> `{stats:{items,news,social,reports,active_jobs},topics:[{name,count}],timeline:[{date,count}],sources:[{name,count}],locations:[{name,count,item_ids}],recent_items,recent_jobs,recent_reports}`. Locations are text mentions, not inferred coordinates.
- `list_accounts()` -> list; `save_account(data,id=None)` -> account; `get_account(id)` -> account or None. Fields id,name,handle,platform,url,organization,status(candidate/verified/excluded),evidence_url,tags,created_at,updated_at. No automatic verification from import.
- `create_job(kind,params)` -> job; `get_job(id)`; `list_jobs(page=1,page_size=25)` -> pagination; `update_job(id,**fields)`; `add_job_event(id,message,level='info')`; `job_events(id)` -> list.
- Job fields id,kind(collect/report/login),status(queued/running/succeeded/partial/failed/cancelled/interrupted),params,result,error,progress(0..100),created_at,started_at,finished_at,cancel_requested. JSON decoded in responses. `recover_jobs()` marks stale running jobs interrupted, leaves queued jobs. `claim_job()` atomically returns oldest queued as running or None. `request_cancel(id)` sets queued job cancelled or running cancel_requested. Retry creates NEW job.
- `import_social(items,accounts,relations)` atomically deduplicates account keys, maps author IDs, preserves capture metadata and saves directed observed relations. Social records deduplicate by original URL; identical text posted by distinct authors retains provenance. Imports never overwrite manually verified status. `account_relations(id)` returns observed relations and explicit evidence gaps.
- `save_report(data)` -> report. Fields title,start_date,end_date,mode(evidence/ai),markdown,snapshot,source_count,job_id. Unique immutable ID and content stored in DB. `list_reports(page=1,page_size=25)` -> pagination; `get_report(id)`.

## Pipeline interface

- `enrich_item(data)` -> normalized dict for import; must preserve publication-date unknown status, candidate attribution. Uses existing public content cleaning and taxonomy.
- `collect(params)` async -> `{items, diagnostics}`. params source(rss/google_news), keyword,start_date,end_date,max_records,feed_url(optional). Real RSS/search via existing fetcher adapters; bounded timeouts and concurrency. No external collection at import time.
- `build_report(items,params)` async -> `{title,start_date,end_date,mode,markdown,snapshot,source_count}`. params title,start_date,end_date,include_news/include_social,mode(evidence/ai). No silent AI fallback. Evidence mode explicitly not AI. References limited to provided source IDs/URLs, immutable input snapshot. Empty dataset is error. Candidate social material excluded from main conclusions.
- `capabilities()` -> `{collectors:[{id,name,state,detail}],llm:{configured,model}}`. State ready/unverified/requires_login.

## HTTP /api/v2

- GET health, overview, capabilities, social (runtime and session presence, not inferred login validity)
- GET items (filters above), items/{id}; POST items/import `{items:[...]}` -> import result
- GET accounts -> `{items:[...]}`; POST accounts / PATCH accounts/{id}; POST accounts/{id}/verify `{verified:bool,evidence_url:str}`
- GET accounts/{id}/relations -> `{items,total}`.
- POST jobs kind=login params `{platform:twitter|instagram,method:'auto'}` checks existing sessions; `method` defaults to `auto`, including older queued jobs without that field. No `profile_id` is accepted in auto mode. Result includes `{ok,method,platform,verified,saved,source,state,requires_login,code,message}`. A ready saved workbench session returns `verified:true,saved:false,source:'workbench',state:'ready'`; a successfully imported Firefox session returns `verified:true,saved:true,source:'firefox',state:'ready'`. A completed check may have `verified:false`; job success alone never means authenticated. Missing reusable state yields `requires_login:true`; challenge, rate limit, runtime failure, ambiguity and uncertain verification produce their own non-ready states without silently trying another account. The runner bounds this task to 110 seconds and checks cancellation before saving.
- GET social/browser -> `{available,name,mode:'system_default',detail}` reports the OS URL-opening capability, not browser login state. POST social/browser/open `{platform:twitter|instagram}` dispatches only `https://x.com/home` or `https://www.instagram.com/` through Windows ShellExecute, macOS `open` or Linux `xdg-open`. Success returns `{opened:true,platform,mode:'system_default',login_verified:false,session_imported:false,message}`. `opened` means the OS request was dispatched, not that page contents were inspected. The UI invokes this after auto returns `requires_login:true`, or on an explicit open action; the auto backend does not open a browser itself.
- GET social/firefox-profiles -> `{items:[{id,name,default,available}]}` reads only `profiles.ini` and file availability, never Cookie values or passwords. IDs are opaque; responses do not include filesystem paths. A configuration's name/default marker does not establish the signed-in account identity.
- POST jobs kind=login params `{platform:'twitter',method:'firefox',profile_id:<opaque id>}` retains explicit X profile selection. Missing/unregistered IDs and arbitrary filesystem paths are rejected. Automatic reuse supports both platforms through the same importer; the explicit profile-selection API remains X-only. X reads only `auth_token`, `ct0` and optional `twid` on `x.com` / `.x.com`; Instagram reads only `sessionid`, `csrftoken` and optional `ds_user_id` on `instagram.com` / `.instagram.com` / `www.instagram.com`. Schema, expiry, security and scope are validated; container, partition or duplicate-scope ambiguity is rejected. A fresh context must confirm the platform's authenticated home before backup and atomic replacement. Cancellation before saving or verification/save failure preserves the original workbench session. Windows and macOS profile-index locations are supported in code; macOS session reuse has not been validated on a real machine.
- Explicit `method:'manual'` remains a compatibility / advanced API for the former visible, bounded 10-minute login task; it is not the default or the normal UI login flow and does not accept `profile_id`.
- POST social/bridge/start `{platform}` uses the normal authenticated workbench API and returns `{platform,pairing_url,expires_in:300,verified:false}`. `pairing_url` is exactly `http://127.0.0.1:{port}/api/v2/social/bridge/connect?code=<64 lowercase hex>&platform=twitter|instagram`. It is a transfer descriptor for the extension, not a GET login endpoint. The extension rejects extra/duplicate parameters, userinfo, fragments, alternate hosts/schemes/paths and redirects; it derives only this local origin.
- POST social/bridge/pair `{code,platform}` is accepted only from a real `chrome-extension://<32-character id>` Origin with a valid one-use, five-minute code. It returns `{bridge_token,platform,expires_at}`. The token is bound to that extension Origin and platform, expires after at most 24 hours, and is lost when the backend process restarts. Pair/sync use their own narrow authentication and CORS rules, never the workbench's full session secret.
- POST social/bridge/sync uses header `X-Workbench-Bridge: <token>` and JSON `{platform,cookies:[...]}`. Exactly two required and at most one optional allowlisted cookie are accepted, with exactly `{name,value,domain,path,secure,httpOnly,expires,sameSite}` fields. Required pairs are X `auth_token` / `ct0` and Instagram `sessionid` / `csrftoken`; optional IDs are `twid` / `ds_user_id`. Domains match the importer lists above, path must be `/`, secure must be true and the authentication cookie must be HttpOnly. Duplicate names, invalid expiry/scope/attributes and unexpected fields fail. A live authenticated homepage check must pass before saving. Success includes `{verified:true,saved:true,platform,source:'browser_extension',state:'ready'}`; failure preserves the previous state. `bridge_busy`, `challenge`, `rate_limited` and other server codes use the standard error envelope below.
- The extension initially requests optional cookies/site/loopback permissions on the user's connect action, reads only fixed URL/name/path combinations, and stores token/configuration/status but never cookie values. After pairing, relevant cookie changes schedule bounded debounced sync; explicit sync and disconnect are available. It neither visits arbitrary destinations nor sends session fields outside the paired loopback workbench. Disconnect stops future extension sync and drops its local binding; it does not delete an already saved workbench session or cancel a request already sent.
- POST jobs `{kind,params}` -> job (202); GET jobs -> pagination; GET jobs/{id} -> job with events; POST jobs/{id}/cancel; POST jobs/{id}/retry (202)
- GET reports -> pagination; GET reports/{id}; GET reports/{id}/download (Markdown)

Errors: non-2xx with `{error:{code,message,details?}}`. No 200 empty lists on infrastructure failure. Frontend distinguishes absent data / failed load / busy / partial success. Dates are local calendar strings, never ISO UTC slicing of local midnight. Polling single-flight and stopped on navigation/unmount. Hash navigation supports overview,library,accounts,reports,jobs,settings. Event/geographic displays must derive only from saved evidence; no invented event records.

Social collect params: source twitter/instagram; mode keyword/account/hashtag; keyword or handle; start_date/end_date; max_records 1..100; max_accounts 1..10; max_scrolls 1..20; include_following; max_following 0..50 (whole task); relevance focused/broad. Unknown dates excluded from date-scoped live collection and explicitly counted. Instagram keyword mode discovers accounts then reads their details; this is not a complete platform-wide text search. X keyword/hashtag modes use live/latest search; account mode navigates directly to the selected account's profile and reads a bounded number of incrementally scrolled viewports. It independently checks primary author, body, date, keyword/hashtag when applicable, and domain relevance. Account mode requires the primary post author to match the requested handle; neither profile membership nor platform ordering establishes authorship or relevance. The collector deduplicates primary post IDs and stops on bounded repeated stalls; it does not promise full historical coverage. Ordinary permalink anchors are not quote containers. Article cards without post body are counted and skipped within bounded scrolling, never substituted for body evidence. Limit/rate/challenge failures preserve structured diagnostics; cancellation closes its browser context.

Normal user flow: Settings -> detect/reuse existing login -> verify workbench state -> when missing or explicitly unauthenticated, verify authorized default Firefox state -> save only after success. If no reusable state exists, the UI requests the OS default browser's official page. Returning from that page requires another verified reuse or a separately paired Chrome / Edge extension sync; opening a browser alone never changes the session to ready. Collection uses saved platform-specific state. A single login lane, including auto and explicit Firefox imports, is independent of the serial collection/report lane; both are cancelled/joined at shutdown, with commit completion protected. The older explicit manual mode retains its bounded behavior but is not used by this normal flow.

Acceptance boundaries: the earlier Firefox UI import and positive X-profile / Instagram-tag collection, repeat deduplication and combined social evidence export were verified in isolated QA data. The actual Windows application data directory was separately found to lack that session; this gap has now been repaired and checked by two live X-home auto runs: first `source:'firefox',verified:true,saved:true`, then `source:'workbench',verified:true,saved:false` (`actual-desktop-auto-session-acceptance.json`). This evidence proves current session reuse at the real data directory, not a full new packaged-EXE workflow. The OS-open endpoint was exercised and opened the current default Firefox; browser-content inspection through the computer-use tool was blocked by its unsupported-URL policy, so no browser-content acceptance is claimed from that tool. Chrome / Edge extension source passed 75 offline tests and eight synthetic backend compatibility vectors but has not been installed or verified in a real browser. The real-directory Instagram auto check correctly returned `verified:false,saved:false,requires_login:true,code:'missing_session'`, because the default Firefox profile had no reusable Instagram session; it neither opened a login window nor saved Instagram state (`actual-desktop-instagram-auto-session-acceptance.json`). This does not prove a successful Instagram Firefox import. Positive X keyword-search retrieval has not been demonstrated: unrelated returned posts were rejected. Current delivery targets are Windows x64 and macOS Apple Silicon; Intel Mac packages are historical only. Apple Silicon native acceptance remains deferred by the user. Runtime and packaging acceptance remain separate from this interface contract.

## Design

Constructivist editorial research console, inspired by EVA information graphics without copyrighted assets: warm off-white, ink-black, vermilion red, restrained amber, strong rectangular grids, bold Chinese headings, oversized condensed numerals, diagonal signal stripe, vertical annotations. Red used deliberately; reading surfaces stay calm. Good mobile stacking, visible focus, reduced-motion handling, no decorative fake telemetry.
