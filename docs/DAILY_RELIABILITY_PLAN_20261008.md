# 日常使用可靠性计划 · 2026-10-08

接续 `-recovery-candidate`，根据当前源码与隔离反例修复真实使用中的数据丢失、重复排队和配置状态问题。整体产品持续完善目标保持原样；本轮通过不代表 Mac 原生、外部平台完整历史、大批量产量或耐久性已完成。

## 已确认问题

1. 提交任务 A 后继续编辑为 B，A 的迟到确认会清除本机与后台的 B 草稿。
2. JSON 文件读取迟到，会覆盖用户随后手动输入或新选文件。
3. 本机已有输入后，迟到的后台草稿 GET 会悄悄更新写入版本，使另一窗口的草稿被无冲突提示覆盖。
4. 单任务与任务串的重试没有统一后代关系，同一失败分支可排入多份相同工作；更深层后代正在排队时，原任务串仍认为可重试。
5. 工作已保存，但终态写入暂时失败后，执行器会领取下一任务，原工作长期停在 running。
6. 研究续查已排队，研究状态仍为上次结束状态，页面无法正确提供排队工作的停止操作。
7. AI 连接 PUT 已应用但响应迟到时，保存报错、磁盘仍旧、运行配置已新，尤其清除密钥时会发生不一致。
8. 可选 AI 配置损坏或系统无法解密时，会阻止整个桌面启动，也无法通过设置页重新配置。
9. 独立复审实际构造出可通过恢复预检、但重试立即崩溃的部分完成记录：`result.summary.stop_reason` 为数组或对象。预检须拒绝坏类型，同时保留缺失、null 和正常字符串的旧备份兼容性。

原始证据位于 `C:/Users/wwx/Documents/New project 7/output/daily-hardening-20261008`。全部使用临时 SQLite、主进程 VM 或拦截请求的 Chromium；未操作正式用户资料或凭证。

## 必需结果

- 创建确认只清除对应的已提交草稿；后续修改、其他窗口版本和已经离开的页面保持有效，任务本身仍保留。
- 文件读取只填充仍对应当前选择且未被继续编辑的输入。后台草稿版本只能在实际采用该草稿或明确重新同步时更新，保留 CAS 冲突保护。
- 后端在写事务中统一解析单任务和任务串的持久重试后代；同一分支已有工作时不多排队，成功后代不重做，后代失败仍可显式重试。
- 已完成结果在终态保存失败时保留并补写，该执行 lane 在确认收尾前不领取下一工作；退出与取消不把已提交结果改成失败。
- 续查预约原子同步研究 queued 状态与阶段，保留原断点、材料和图谱。
- 配置请求结果不确定时，从未变的磁盘配置重建后台并给出可读结果，不能让迟到请求继续修改当前服务。
- AI 配置读取失败时，保留原件、禁用不可读取的 AI 凭据、正常启动研究和证据整理，并在设置页明确说明。显式保存新配置前保留原加密文件，错误信息不含密钥或解析原文。
- 恢复预检共用持久重试关系解析，拒绝缺少父任务、类型不同、错误根任务、循环和损坏的停止原因；源备份字节不变，正常旧字段仍可读取和重试。
- 重新构建 Windows x64 / Apple Silicon 成品，核对源、manifest 和包内字节，实际 Windows 进程与原有备份恢复、私有 HTTP 流程重新验收。
