## 已实现的变化

| 问题 | 本批行为 | 保留的准确性要求 |
|---|---|---|
| 不同审核任务重复读取同一网页 | 默认复用一小时内成功捕获，另可强制刷新或关闭跨任务缓存；显示捕获时间、时效和读取计数 | 校验原始字节、提取器版本和内容；关闭网络不可借缓存读外部来源；每个目标的身份依据独立投影 |
| 大报告重试时重新导出已经变化的研究上下文 | 付费分析前持久化完整输入；原输入续跑与最新输入重新生成分开选择 | 不把最新资料伪装成旧输入；阶段复用继续检查完整指纹和证据 |
| 旧报告只保存阅读记录，没有完整原输入 | 免费预览明确原输入不可恢复，按最新材料比对可复用阅读 | 缺失历史上下文时，变化数量为未知；不承诺只需补最后一次模型输出 |
| 预览后来源或审核结果变化 | 提交时再核对输入 SHA，冲突后必须重新预览 | 不创建使用过期输入授权的新任务 |
| 新增完整快照导致状态响应膨胀 | 状态接口仅输出摘要，Store 仍保存全文 | 独立报告及来源导出保持完整 |
| 审核任务沿用 collect 类型导致授权判断不准确 | 自动审核任务的取消、重试按 review 权限校验 | 普通 run 权限不能重启审核；登录和会话任务仍不可操作 |

缓存有 128 项、32 MiB 的正文和提取载荷容量限制，满后清理派生副本，不删除保存材料或独立报告。该数字不是整个数据库文件的磁盘上限。旧完整备份可在恢复 staging 中补齐已知派生缓存表，原备份不改写。

## 测量说明

固定离线样本的两个自动审核任务各处理两批，共四轮工具调查、八次实际工具调用和四批原子结果保存。默认复用模式合计获取网页一次，关闭复用、强制刷新和影子比较模式均为两次；第二任务默认模式没有新获取。从完整 checkpoint 再续跑为零新获取、零新工具调查轮次。

原七场景比较扩展到四种策略：每种十四次来源核对，默认复用需要七次获取，另外三种策略均为九次。两个独立测量运行的核心结果一致，原输入夹具保持同一哈希。样本包含账号目标隔离、来源登记变化、过期、内容变化、取消、损坏和清理；没有调用真实模型或公开平台。

真实历史记录提供了不同边界：最近的账号/关系审核有 54 次外部网址读或引用核对工具调用，涉及七个网址；活动审核有十二次，涉及五个网址，两个任务的确切网址交集为零。这些是工具调用记录，不能视作实际网络请求量。没有证据表明新缓存会缩短这两个已经完成的历史任务，也不能据夹具推算固定的账单节省比例。
