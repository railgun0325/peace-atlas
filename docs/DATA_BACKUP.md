# 研究数据备份与恢复

在“能力与设置”点击“备份研究数据”，将下载的 `peace-atlas-backup-时间.sqlite3` 保存到备份位置。应用运行中也可以备份：备份包含下载时已经提交到资料库的数据，不包含尚未完成保存的任务结果。

备份包含资料正文与来源、组织账号、公开关系、研究发现与断点、人工核对、报告及其输入快照、任务历史、任务串和服务端草稿。登录会话、浏览器配置、AI 密钥和日志保存在数据库之外，不随这份研究备份下载。草稿尚未同步到服务端的输入也不在数据库快照中。

## 验证和保管

下载失败时界面会显示实际错误，不将错误响应当作备份文件保存。生成完成的备份是独立 SQLite 文件，已包含原库 WAL 中提交的数据，无需同时下载 WAL 或 SHM。保留多份不同日期的备份，避免新备份覆盖唯一的旧备份。

## 恢复到现有桌面应用

桌面 `-recovery-candidate` 及以后版本可直接使用“恢复研究备份”：

1. 打开“能力与设置”，点击“恢复研究备份”，选择之前下载的独立 `.sqlite3` 文件。
2. 应用先只读检查备份的完整性、表结构、保存时间及报告／研究内容。检查通过后，原生确认窗口显示备份文件、记录数量和需要中断的任务数量；确认前不会替换当前资料库。
3. 确认后，应用停止当前后台，将原库及存在的 WAL／SHM 保存在当前数据目录下的 `restores/before-时间-随机标识/`，安装已检查的候选库，再重新连接后台。界面显示成功和原库存档位置后，核对资料、报告、研究和草稿。
4. 备份中的排队与运行中任务全部变为“已中断”，等待你在任务中心手动重试。已完成和部分完成的历史保留；不会自动重放备份中的任务。

备份源文件保持原样。恢复只替换研究数据库，当前电脑的平台会话与系统加密的 AI 配置保留。如果新库启动失败，应用尝试恢复原库。若异常退出后无法确认旧服务已经终止，或原文件集合无法核实，应用会停止恢复并保留事务记录、原库存档和失败候选，避免继续创建空库；此时可打开日志和数据目录查看实际错误，不要删除这些证据后反复启动。

需要回到恢复前的数据时，可再次选择归档中的完整 `workbench.sqlite3` 使用恢复按钮；如果归档仍含非空 WAL，应按下面的退出后人工恢复方式一并恢复整个原文件集合。恢复按钮只接受已完成的独立 SQLite 备份，不接受正在使用中的原库或其未合并 WAL。当前兼容范围是本产品的 V2 SQLite 结构，不承诺任意旧版或其他软件数据库的自动迁移。

### 退出后人工恢复

较早桌面版本或无法使用原生恢复按钮时，保留以下人工步骤。人工方式的排队任务处理与上述按钮不同：

1. 在“能力与设置”点击“打开数据目录”，记下打开的文件夹。随后从应用菜单“退出”，等待应用正常关闭。
2. 将整个数据目录复制到另一个安全位置，作为恢复前的回退副本。保留现有登录会话与连接配置。
3. 在数据目录新建一个独立的旧库存档文件夹，将 `workbench.sqlite3`、存在时的 `workbench.sqlite3-wal` 和 `workbench.sqlite3-shm` 一并移入该文件夹。操作时应用必须已经退出。
4. 把下载的备份复制到数据目录根部，副本重命名为 `workbench.sqlite3`。不要给恢复的新库保留旧库的 WAL 或 SHM。
5. 重新打开应用，核对资料、报告、研究和草稿。备份中的运行中任务会标记为中断；排队任务按原有队列规则继续执行，请在任务中心核对所需工作。

如果恢复结果不符合预期，退出应用后将恢复库及其 WAL/SHM 移到另一个文件夹，再把第 2 步保存的原数据目录恢复。这样可以回到恢复前状态。

## 换电脑

在目标电脑启动一次应用，使用“恢复研究备份”选择独立备份，或按上面的人工方式退出后复制。登录会话和系统加密的 AI 配置需要在新电脑单独建立；不要把旧电脑的系统加密文件当作可跨电脑恢复的密钥备份。

## 开发与验收

SQLite 在线备份使用数据库自身的 backup API，并在下载前执行完整性快速检查。临时快照在传输完成或失败后清理。接口为 `GET /api/v2/backup`，遵守工作台会话验证。

使用 PostgreSQL 的源码或服务端部署应使用对应数据库的备份工具；该按钮会显示当前不支持。桌面应用固定使用 SQLite。

`scripts/verify_product.py --output-dir <独立验收目录>` 可验证实际后端的资料导入、报告生成、下载、备份、重启与独立资料目录恢复。它使用确定性公开材料样本，不调用外部采集或 AI，验收结果不能代替外部来源实采。

桌面原生恢复的独立 SQLite 验收使用 `scripts/verify_restore_evidence.py`；父进程退出与保持父管道打开时的正常关机使用 `scripts/verify_parent_lifecycle.py`。测试配置显式指定隔离资料目录，不使用正式用户资料。具体结果及失败保留记录见本轮恢复验收文档。
