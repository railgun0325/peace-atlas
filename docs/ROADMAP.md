# PEACE ATLAS 路线图

本路线图由 [基础架构复审](FOUNDATION_REVIEW_20261011.md) 提出。各阶段都是规划；勾选或阶段名称不代表已经实现。版本、测试与真实任务事实见 [发布验收](RELEASE_20261011.md)，此处不维护正在运行任务的计数或进度。

第一批来源复用、报告固定输入恢复及对应测量另见 [实现记录](FOUNDATION_IMPLEMENTATION_20261011.md)。它只完成路线中的有限切片，不代表下列整个阶段均已验收，也不改变旧发布版本的能力范围。

历史质量版事实集中于[质量发布记录](RELEASE_QUALITY_20261011.md)，后续引用反馈、输出容量和补读候选的独立结果见[收尾验收记录](RELEASE_FINAL_20261011.md)。2026-10-11 真实 601 条来源试点已完成逐条阅读，并实际验证原输入续跑保留已完成阅读和 DSH 工具记录；这不代表跨独立报告的付费阅读缓存已经实现，也不把仍在运行或被结束校验拒绝的报告视为验收成功。

**目标：以问题为起点，复用既有证据，增量补齐缺口，提供可恢复、可核查且成本可解释的持续研究。** 保留 SQLite、现有工作台 UI 和 DSH 受限模型工具循环。每阶段交付一个能独立比较、关闭与回退的改进，再决定是否扩展。

## 1. 基线与决策规则

复审基线已有来源版本、研究分支 checkpoint、显式续查、候选与审核分离、证据网关、批提交事务及有界模型传输恢复。基线版本的回归总量为 **2939 = 2688 后台 + 172 前端 + 62 桌面 + 17 构建检查**；后续版本的实测另见实现与发布记录，不能把测试数量当成本路线图收益的测量结果。

路线优先级依次为：证据分层与测量 → 跨任务复用/增量及单项恢复 → 问题缺口规划、检索与提取 → 资源调度和薄 MCP。正文提取的离线 A/B 可以提前并行开展，正式替换依赖来源版本契约；大框架只在试点证明能减少现有复杂性时引入。

所有阶段遵守三个推广条件：

1. **收益可重现**：同一冻结样本、预算、日期和目标下比较；指出收益来自缓存、采集、检索、提取、排序还是调度，避免一次全换后无法归因。
2. **真值要求不退化**：新增声明、计划与日期部分信息不能升级为官方身份、政治成员资格或已确认地图活动；逐字引用不替代完整语义支持。
3. **迁移可恢复**：保留旧数据与历史审核；新增能力能停用，索引能重建，失败/取消/中断终态可解释，兼容路径经过实际回归。

尚未测量的性能目标先留待基线填写。规划可以明确“故障样本零结果丢失”等正确性要求，不虚构吞吐、精度、成本提升比例或组件包体大小。

### 当前反例确定的优先修复切片

以下反例确定了后续切片；来源阅读诊断、自动恢复和时间校准仍是待实施计划。第 3 项的精确反馈、输出容量和补读条件历史通过 320 项相关及 3,174 项整套回归，但真实 601 条恢复仍因未经工具核对的摘录失败。本轮进一步实现显式版本的引用凭据：344 项相关及 3,198 项整套回归、新 Windows 包内 SDK、本机原生与 23 张表升级通过，真实原输入续跑新增 17 次工具后在第 1 条 finding 的第 1 个 quote 被无效收据校验拒绝，未保存报告。取证、最终报告与新云端分发的完成状态仍由各自实际结果决定：

1. **来源阅读错误可定位**：当前通用错误合并部分 HTTP、连接超时、外层响应 JSON 和模型响应 envelope 问题。新增固定分类、尝试序号、有效超时、耗时、HTTP 状态及响应长度/hash；不保存响应原文、请求头、密钥或配置。来源批的 `attempts` 目前主要记录摘录修正，空数组不能解释为没有请求或没有费用。
2. **有限自动恢复**：在来源阅读调用处对明确可恢复的传输错误建立最多三次、共用截止时间的恢复；先保留诊断，再决定重试。内容格式、语义、摘录、取消、永久 4xx 和截止时间错误不靠盲目重试解决；无法确定已发送请求结果的超时保留不确定性。已校验单项不重复读取，累计记录不冒充提供商账单或端到端 exactly-once。
3. **Harness 最终摘录精确反馈（源码已实现）**：原来合并的 quote 字段形状、所属 finding 引用和成功阅读记录三类错误，现在分别记录固定 subtype 和从 1 起始的 finding/quote 位置；不记录任意 ID、摘录或候选正文。“最后已发送修正反馈”和“最终失败诊断”分别保存，诊断先于修正额度检查持久化。原输入恢复带入安全位置及固定指导；旧记录缺少位置时保持未知，不根据旧反馈猜测最后一次失败。标准报告指导明确 `check_citation.exact_quote` 与结束对象 `quote` 的差别，自动审核的自定义 validator 保持自己的契约。累计最多两次修正、已读材料绑定、逐字引用和语义复核要求保留；改进效果由新包和真实任务结果证明。
4. **预估与进度校准**：以实际任务的读取、工具、压缩、复核、排队和恢复耗时建立分阶段统计，明确样本量与适用范围。当前数量级预估没有这批长任务的实测校准，不能当作运行时间保证。

验收首先重放已保存的失败类别与受控故障，在同一输入下确认正确终态、固定修正上限、父记录不变、已完成项零重做及诊断零原文泄露，再执行真实模型小范围和长任务试点。诊断改善、自动恢复、跨任务复用和检索改进分批测量，避免把任务偶然成功归因给尚未实施的功能。

真实恢复还暴露出工作流瓶颈：来源全量审阅、工具阅读、逐字核对与结论提交是独立阶段，模型从长历史自由重写摘录可能丢失已经核对的绑定。本轮已实现合格摘录目录与版本化引用凭据， host 重新核验当前来源、原句和实际读取窗口后按原严格合同还原；收益仍须由真实续跑证明。后续再分别比较具体证据待办与有进展条件的修正资源配置。预算变更须保留累计消耗和版本语义，不能清空旧纠正次数、伪造工具读取或放宽引文与语义校验。

## 2. 阶段 0：冻结可比较的基线

**交付**：一套去标识化、可重复运行的来源/账号/命题/活动样本，人工核定关键答案与证据边界；当前检索、提取、审核、续查和队列的测量脚本及收据。真实平台、真实模型试点与离线 fixture 分栏记录。

样本覆盖：组织官网与新闻正文、摘要/短预览、聚合页、同标题错正文、登录/订阅/失效/PDF页面；日/中/英查询、两字短词、别名、同名主体、否定与反证；明确自述与仅用户名、身份限定缺口；计划/报道/缺年/多日期/地名提及/实际举办；转载簇、只变一条来源、只变研究目标、新旧混合任务，以及工具/保存前后取消与退出。

| 指标组 | 必须明确的分母与观测量 |
|---|---|
| 获取 | scanned、新 unique capture、浏览器/HTTP 时间、实际覆盖日期区间、未读缺口、重复前缀量 |
| 有效产出 | 有用资料/捕获量、有用资料/模型输入量、独立证据与有效命题/成本；未分类随机抽样，不把未分类当无关 |
| 复用 | 原文/来源调查/命题缓存命中、重复网络读、重复模型输入及 token、结果失效原因 |
| 检索 | Recall@20、精确率、关键反证召回、日期/主体/回收站过滤、短词与 literal `%/_`、p95 延迟 |
| 提取 | 正确正文覆盖、推荐/评论/页脚污染、错正文、受限页误接受、来源地址与提取完整性标记、CPU/内存/p95 |
| 审核 | 假确认、错误主体/对象/限定/年月日、来源独立性、具体缺口、纠正轮数、工具与模型调用/最终决定 |
| 执行 | 排队/执行/checkpoint p50/p95、状态字节、重复提交、已完成项重做、外部调用不确定状态、无主 running |
| 桌面成本 | 新增依赖、冻结包文件/字节、许可闭包、离线加载、Windows/Mac 原生结果与失败记录 |

**可复验验收**：冻结样本与参数有 hash；人工答案包含“不能判断”的原因；相同输入能够得到可比收据；当前行为与真实访问限制明确保存。不能用无标准答案的字符数、文章数或模型自评代替基线。

## 3. 阶段 1：证据分层与部分信息表达

**交付**：新增来源表达与事实确认字段、来源版本/片段合同；UI/API 给出范围明确的投影，沿用现有布局与入口，不增加一套审批流程。

- 账号分别存来源声明类型、观察用途、证据支持的主体类型和严格核验身份。每层记录 quote、capture hash、时间、方法和适用范围，人工锁定与 verified 保持原义。
- 活动分别存来源说法、时间原文与精度、地点角色、实际发生核验和地图资格。计划、报道声称举行和缺年信息可检索、可用于带归属说明的报告，不能直接进入确认统计。
- 日期样本须包含日文月日分隔写法（如 `11・1`）、全文有年份但引用窗口漏掉年份、预告与回顾混排等情况。明确区分“来源缺少信息”“摘录缺少上下文”“格式未识别”和“尚未证明已经发生”，据此选择补读、解析或保留计划状态，不能用重复完整审核代替缺口处理。
- 原始捕获、待判候选、目标相关材料和正式结论证据分别路由。相关性绑定目标；高置信无关退出本次模型输入，保留原文，歧义与反证不误排。
- 所有主张绑定主体、对象、关系、身份限定、来源版本和支持范围；转载与多次捕获不等于独立来源。

**可复验验收**：已有 unknown/verified、人工锁定、历史观察与报告快照不被自动升级或覆盖；明确自述能保存为 self-described 而官方身份仍待核验；仅用户名保留未知；部分日期不补年；计划和地名提及不进入地图分母。固定身份/成员/活动反例假确认数为 0，错误时保留原输入与失败收据。

**停止条件**：若新增字段在显示、过滤或报告中无法保持这些区别，先修复投影与合同，不扩大自动回填。字段抽取只消费明确原文，不为了填满字段推断普通个人政治身份或组织成员资格。

## 4. 阶段 2：跨任务缓存、增量采集与单项恢复

**交付**：共享来源捕获/阅读缓存、规范命题映射、采集 coverage 与 work ledger。继续使用应用数据库作为业务真值，不引入第二套资料库。

按三个独立里程碑推进：来源阅读复用 → 一个采集入口的覆盖记录 → 单项恢复。每一步保留关闭开关和固定输入的前后对照。先用两批读取同一来源的离线样本测读取次数、模型输入和权限投影，再验证只改来源版本或研究目标的失效范围；不同时替换整套流程。

来源缓存按规范 URL、capture hash、提取器/策略版本建立；失败带类型与 retry-after。事实抽取和逐字核对可复用，目标相关性与最终判断按问题单独计算。命题规范化保留限定和观察，不合并不同主体、地区、职务、刊物或时间的主张。

缓存保存共享内容与片段，登记出处权限及最终身份结论在使用时重新按目标投影。同一页面被两批使用时，只有准确登记的账号可以使用该登记依据，其他账号不能通过缓存继承权威。适用期内命中与到期刷新分别计数。

增量采集保存平台/账号/查询边界、已知 ID、日期覆盖和刷新窗口。稳定 cursor 只在真实支持的平台使用；其他页面采用重叠窗口与连续已知内容停止。关注列表记录时刻与变化，不能永久视为已完成。

连续已知内容只是扫描停止条件，不证明日期区间无缺口。固定样本须覆盖置顶、乱序、分页重叠和已知前缀夹新内容，保存实际扫描范围及未读尾部。

work item 保存输入/依赖 hash、操作键、调用预留及完成收据、状态和累计预算。模型可按批处理，但已校验单项结果能够持久保存。原子最终提交、记录版本比较和取消守卫继续执行；未知外部调用不能默默重放，也不能宣称端到端 exactly-once。

**可复验验收**：

1. 在缓存适用期内重复同一已完成、不变资料和问题时，不新增付费来源阅读；到期刷新另行计数。改变问题复用原文和适用事实，重新做目标相关判断。
2. 只改变一条来源或限定，只使依赖结果失效；历史报告仍绑定旧来源。
3. 在第 N 项、工具返回、保存前后及进程退出注入故障：已提交结果不丢失、不重复，合法完成项不因其他单项坏输入消失，累计预算与 receipt 一致。
4. 重复账号采集比基线少读已知前缀，已知新增和日期缺口不被漏报；“无新内容”只描述实际扫描范围。
5. cache hit、扫描/新增、复审 token、checkpoint 时延和字节均有原始收据；正确性通过后才依据实测填写效率目标。

**兼容迁移**：先新增表/映射并做影子比较；旧 claim ID、研究版本和审核记录不重写。缓存与索引可重建；关闭新调度/缓存可继续使用旧读取路径。回填不得把旧来源自述提升为事实确认。

## 5. 阶段 3：问题缺口规划、检索与正文提取

**交付**：小型问题/命题清单、证据缺口与竞争解释、候选动作和预期成本；可回原文片段的检索合同；提取器与召回策略的 A/B 收据。

行动优先级先由规则、已保存来源、过去分支实际产出及成本计算。模型补充剩余歧义和下一步调查，不再每次重读全库。保留探索额度，测低分/新领域候选是否被长期饿死。停止理由为目标满足、可读来源耗尽、连续行动无证据变化或用户资源边界；固定轮数只是边界，不是自治质量。

检索先比较精确字段、别名和全文索引。SQLite FTS5 要核对包内支持、CJK/短词、转义与索引一致性，保留两字查询回退；不能把 trigram MATCH 直接当现有 substring 的等价替换。[SQLite 官方说明](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

正文提取用 **Trafilatura 作为 A/B 候选**，消费现有安全获取器提供的 HTML；保留 JSON-LD、标题/页面身份、受限页和原摘要守卫。对同一 HTML 比较正文正确性、污染、缺失及成本，优胜才逐站点推广，失败回退；不以更多字符或库名判胜。[Trafilatura 官方 API](https://trafilatura.readthedocs.io/en/latest/usage-python.html)

embedding、混合召回和 reranker 只解决已测得的语义改写或跨语言漏召回；记录模型、索引版本、许可、重建和离线推理成本。全量阅读与按问题选材提供不同覆盖声明。图检索优先使用实际观察与已审核命题，模型抽取边保持候选。

**可复验验收**：同预算下目标覆盖、独立新增、反证发现、无收益行动成本分别比较；召回与精确率分别报告，关键反证不漏；原文片段能定位到确定 revision/offset。固定负面页面误接受数为 0，来源身份/访问边界/完整性标记不退化。两目标包新增依赖、许可、原生加载和资源开销有实测记录。

**停止条件**：若只能增加字符、命中数或账号数，却不能提高有用证据与目标覆盖，继续使用现有路径；检索/提取/排序分别消融，不把一项收益归给整套新架构。

## 6. 阶段 4：资源调度、持续执行与编排取舍

**交付**：资源分类与阶段依赖、owner/lease/heartbeat、有界并发、暂停/恢复里程碑。每个平台/浏览器会话维持互斥；公开 HTTP 和不冲突的保存快照分析可有界并行。短操作不因一项长期研究占住全部普通工作。

先在现有持久队列上验证调度改进，再决定是否引入 LangGraph。其试点只能替换阶段编排，不再运行第二套重叠 Agent Loop；DSH 继续执行受限证据调查，应用数据库保存唯一材料、主张、审核和报告真值。采用需证明删除了重复编排/恢复逻辑，且无需新常驻服务或云 tracing。[LangGraph 官方持久化边界](https://docs.langchain.com/oss/python/langgraph/persistence)

Open Deep Research 已归档，只用于流程与评估设计参考，不作为持续维护运行底座。[官方仓库](https://github.com/langchain-ai/open_deep_research)

**可复验验收**：长任务期间不冲突短任务的排队时长有基线对照；同一浏览器无重复控制，模型并发/成本满足用户约束。跨实例启动不会误中断有有效 lease 的工作。断网、模型失败、休眠、退出和恢复后无主 running、重复提交和结果丢失为 0；无法确定外部调用完成时保留明确状态。先完成小时级演练，再做用户授权的一天级耐久任务，两者不能用测试中的虚拟时间代替。

**停止条件**：若新框架只增加状态副本、checkpoint 体积、依赖或排障路径，保留现有队列；若只能并行但无法保持资源互斥与取消/提交语义，不推广。

## 7. 阶段 5：薄 MCP 互操作

**交付**：官方 SDK 的隔离 adapter，复用当前 Agent API/CLI 的业务 operation、scope、revocation、preview/execute 和收据。先提供证据检索、读取原文和任务状态，再暴露已有授权范围内的受控任务。现有 UI、CLI 与 MCP 调用同一合同。

MCP 不提供事实可信度或操作系统沙箱。adapter 不包含密钥/浏览器会话 resources、任意文件读取、shell 或另一套业务写入逻辑；新增 adapter 不放开 DSH 当前禁用的 MCP 插件。HTTP 继续授权和 Origin/绑定检查，stdio 环境按实际客户端权限处理。[官方 transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[官方安全建议](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices)

SDK 的精确依赖和许可证在试点前锁定；若与当前桌面 Pydantic 锁定冲突，先隔离进程，不直接改变已验证后端闭包。Node 与 Python 方案比较实际包体、启动、维护和两平台加载成本后决定。

**可复验验收**：同一操作经 UI/CLI/MCP 的参数、结果、错误和状态守卫一致；无 read→run/review/cleanup 越权、撤销后调用成功或跨授权对象操作；恶意网页/工具文本不会改变操作范围；错误请求无业务副作用。既有正常业务的预览/确认合同保持，不为只读适配另加用户审批层。参见 [Agent 集成](AGENT_INTEGRATION.md)。

## 8. 不预先承诺的技术与发布要求

Haystack/LlamaIndex、LightRAG、Crawl4AI 和 Scrapy 保留为对应检索、图导航、动态站点或固定站点规模瓶颈的独立候选。出现适配需求不等于要整体安装框架；采用必须写明它替换了什么、保留了什么、实际收益和新增运行成本。

每阶段至少提交：问题与固定反例、实现/兼容迁移、基线对照、失败收据、对应回归、退出/取消路径、停用/回退方法。每批执行相应行为测试，交付前做整体与包审计，前端在实际浏览器验收，桌面进行隔离 profile 原生路径及两目标依赖检查。按 [项目协作要求](../AGENTS.md)、[构建说明](../desktop/BUILDING.md) 和 [备份恢复](DATA_BACKUP.md) 执行。

阶段完成记录必须分别列出“已写入”“已回归”“已真实平台获取”“已真实模型运行”“已原生设备验收”。正在运行或部分保存的任务不写作整体完成；流程成功、信息表达完整、事实核实和目标覆盖各用自己的指标。验收事实集中于 [发布验收](RELEASE_20261011.md) 及后续对应版本记录。
