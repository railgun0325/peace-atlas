## 实际分析链路

保存材料逐条阅读与摘录复核 → DSH 工具调查 → 综合报告生成 → 引文和报告复核 → 保存报告及取证快照。

集成使用官方 `@deepseek-ai/harness-sdk` 与对应 runtime **0.2.0-rc.2**，固定在同一版本。真实桌面链路为包内 Python → Electron 自带 Node → SDK 自有的 DSH 子进程 → Agent Loop → 已登记的七个工具。无需用户另外安装 DSH 桌面应用。SDK 参考：[官方 SDK 说明](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.0-rc.2/packages/sdk/client/README.md)、[对应发布](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.0-rc.2)。

| 工具 | 使用范围 |
| --- | --- |
| `list_evidence` | 在本次保存的材料中查找和列举证据 |
| `read_evidence` | 阅读保存正文的明确字符区间 |
| `inspect_account` | 检查保存账号资料、登记类型和核验出处 |
| `trace_observed_path` | 沿有来源的已观察有向关系查询最多三跳路径 |

| `compare_evidence` | 比较多条证据的说法及差异 |
| `check_citation` | 核对摘录是否准确出现在对应保存正文中 |

工具阶段形成候选判断、调查重点、证据缺口与下一步建议。工具输出不授予核验身份，不把自述或关注升级为已证实隶属，不把结构位置认定为政治影响力。报告上下文含本次已知账号和公开关系；尚未采集的候选不因此自动进入材料范围。当前工具调查使用保存材料，继续扩采仍通过工作台原研究流程进行。

模型调用沿用应用中已保存的 DeepSeek Flash 连接。连接密钥由正常后台使用，临时 DSH 会话通过本任务模型代理获得响应；密钥不写入 DSH profile、命令行或调查日志。每个任务使用独立的临时工作区，取消、失败和正常结束都收尾所拥有的子进程。

## 参数和恢复

从已有研究生成报告时，模型与工具就绪则默认 DSH 工具分析，运行时间 120 分钟。普通报告入口保留证据整理与 30 分钟默认值。默认 24 次模型决策、64 次工具调用；可选整数范围分别为 2–64 和 2–256。较深调查建议 32/96/120 分钟。计数仅约束 DSH 阶段，同一输入的恢复链累计，不是 Token 或收费额度，也不包含前后全文阅读、综合生成与复核。

失败的 AI 报告可使用“调整分析方式并续跑”，只修改调查方式、模型决策次数、工具次数和时间，保留原研究、日期、目标和来源。复用逐字摘录和来源指纹一致的已完成阅读；DSH 绑定材料、研究上下文、阅读、模型和协议，输入变化会重新调查。未完成的工具阶段保留已完成调用记录，在新的任务会话中继续，不假定恢复旧模型的隐含记忆。

只有摘录不属于正文，而响应结构和身份字段均有效的批次，才允许一次有原文约束的纠正。同一阅读恢复链累计最多 12 次，预先保存次数。未知或重复来源、结构错误及其他越界字段不进入此纠正。仍然不合格时保留断点并停止。
