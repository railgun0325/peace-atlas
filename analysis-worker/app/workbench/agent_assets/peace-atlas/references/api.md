# Local Agent contract

The supplied CLI is dependency-free Python 3.10+. Pass global `--connection <private-file>` before the subcommand. The file is explicitly exported by the desktop user, protected for its owner, and stores an independent Agent credential. No desktop session, AI key, login cookie or profile is required by the CLI. Public `manifest` and `schema` can also use `--base http://127.0.0.1:<port>` when the user knows the endpoint.

```text
python <skill-folder>/scripts/peace_atlas.py --connection <file> schema
python <skill-folder>/scripts/peace_atlas.py --connection <file> read items.list --json "{\"query\":\"反戦\"}"
python <skill-folder>/scripts/peace_atlas.py --connection <file> preview research.start --input research.json --output preview.json
python <skill-folder>/scripts/peace_atlas.py --connection <file> execute --preview-file preview.json --key research-20261010-001 --confirm
```

Use an input JSON file when shell quoting differs. The CLI creates output files exclusively and does not overwrite existing artifacts. Keep preview files outside the installed Skill folder.

Read `/agents/v1/schema` for complete, current JSON schemas. Identifiers cannot contain path separators. Unknown operations/extra arguments are rejected. The operation catalog never accepts arbitrary URLs/API paths. Login jobs cannot be mutated by this channel.

Automatic review is a saved `collect` job with `params._evidence_review:true`; fast classification uses `params._account_classification:true`. `job.get` can already read its progress. Its cancel/retry operations require the independent `review` grant, not just `run`; both preview and execution check the actual saved job again. The operation schema exposes this distinction as `scope_by_job`. Do not infer review permission from the generic collection job kind.

For `classify.start`, `account_ids` is optional (default `[]`, selecting all eligible saved accounts) with at most 2000 explicit IDs; `batch_size` is a strict integer 1–200, default 100; `recheck` defaults to false. False selects unreviewed or legacy unknown types, including previously reviewed unknowns. True also selects already known types. Manual-locked and excluded accounts are skipped in both cases. A batch normally uses one non-thinking model call, with extra attempts possible on transport failure. The snapshot/input digest is supplied by the preview; do not invent it. The projection contains only each ID, saved display name, handle and public bio. New model results save organization/individual only, high/medium/low confidence, a short reason and `fast_model_classification` provenance. A recognizable collective name and clear collective publishing or operation support organization; mere membership, support, former role or organization mention do not. All other accounts default to individual, possibly with low confidence; this is publisher-form approximation, not verified real-world identity. They do not change account verification status or evidence URL. No public sources are fetched and no identity check is scheduled; model requests still use the configured remote provider. The schema advertises `may_read_public_network:false`, `identity_verification:false` and `manual_locked_skipped:true`.

Fast-classification job cancellation and retry both require `review`. Each committed batch includes its saved progress; a retry follows the same snapshot and skips committed IDs. Stale unsaved input, invalid/omitted/duplicate result IDs or invalid types reject the whole affected batch. Use a fresh classification preview when the current inputs must replace that snapshot. UI manual type corrections lock the selected organization/individual; the separate type-lock release preserves the decision and does not trigger classification. The UI groups legacy unknown with individual, while older saved checkpoints and strict evidence-review records remain unchanged for audit compatibility. These UI controls are not listed as Agent mutations; never construct arbitrary routes to invoke them.

`review.start` remains the slower evidence-investigation path. Its API `kinds` default is all three of accounts/claims/activities; the UI defaults to claims/activities and requires opt-in for account evidence review. Specify `kinds` to make the intended scope explicit. Account identity verification is independently checked and can also be run through the app's candidate-verification controls. Fast type labels do not weaken activity, claim or identity evidence rules.

For automatic review, `source_cache_mode` defaults to `reuse`; `refresh` skips persistent reads but can save fresh successful captures; `off` neither reads nor writes persistent copies. All modes keep the run's own fixed in-memory captures. `source_cache_ttl_seconds` is a strict integer from 1 to 86400, default 3600; it limits cross-run freshness, not job duration. `shadow` is a diagnostic comparison mode, not the normal user choice. Network-disabled review cannot read an external source from persistent cache. Reused source content never confers another target account's identity authority. `job.get` may include `result.source_cache` counters, capture/expiry receipts and an explicit receipt truncation count. Distinguish successful captures from attempted requests and cache reuse from a fresh live read. Legacy jobs without these fields do not have measured cache statistics.

For report retry, first read `job.retry_preview`. `original_input.available` requires a complete validated snapshot; historical jobs without one must not silently switch inputs. Set `job.retry` arguments to `{id,options:{input_mode:"original"}}` to retain that exact input, or explicitly choose `input_mode:"latest"` to use current saved material and review context while preserving the goal/date scope. The mutation preview binds the selected input hash; execution validates it again. Do not invent hashes or reuse a stale preview. Matching fragment fingerprints and quotes are reuse candidates, not proof that DSH, draft or compression can skip execution. Missing historical context makes change counts unknown, not zero. A non-research report with `read_original:true` cannot use latest-input retry because that would skip its requested capture; create a new report to read originals, or use its existing complete original snapshot. Normal status responses expose only the saved input summary; independent saved report exports retain their full source snapshot.

For a write, `/agents/v1/preview` stores the normalized operation/arguments, grant ID, business estimate/cleanup proof and a five-minute expiry. `/agents/v1/execute` requires the exact same normalized arguments, that preview ID, `confirmed:true` and an 8–80 character stable operation key. The server serializes actions and remembers the original result for this grant/backend lifetime. A consumed preview cannot run under a new key. Matching retries return the original response (also on failure); changing arguments under a key conflicts. Revoke/restart invalidates the grant, so idempotency receipts are not a cross-restart recovery mechanism. Query the saved business job ID to resume work after restart.

Initial research calls the same research estimate/confirmation path as the UI. Continuation also uses the current saved run/current-job binding and preserves omitted limits. Zero for max_records/max_accounts/max_edges/time_budget_seconds means no extra stop on that axis; finite date/depth/per-account bounds still apply. Report/collection previews show parameters and whether remote reads/models may occur; they do not claim a measured runtime. Actual execution uses the configured app model when selected, without exposing its key.

Default access is disabled. Every data/action request requires the independent credential, a loopback client and no Origin/Referer header. Browser CORS, remote calls, system proxy routing and HTTP redirects are unsupported. Scope checks precede both preview and execution. Credential possession trusts local processes running as the same OS user; this is not a sandbox against malicious programs already running as that user. Public schemas are not a credential-discovery endpoint.

Review batches bind each target's current evidence hash. Activity hashes are per activity and original source, so reviewing another paragraph does not invalidate sibling decisions. A missing record, changed source or invalid quote rolls back the whole batch. Automatic review saves its decisions and completed progress in one transaction, allowing an explicit retry to skip committed work. Inconclusive claims retain storage status candidate with reviewed_at and public review_outcome inconclusive; they are not pending unreviewed facts. Reviewed activity candidates likewise have review_outcome inconclusive and remain outside the map denominator. Source corrections reactivate activity review. Unknown account types are recorded decisions without granting verified status. Automatic sources require an exact publisher-owned homepage backlink; new authority is not propagated to other accounts on the same site.
